# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Product

LeadPilot is a B2B SaaS that finds forgotten prospects in a CRM export, estimates recoverable revenue and drafts AI follow-ups. It is **not a CRM**. V1 constraints (validated product architecture): max 3 database tables (`utilisateurs`, `prospects`, `relances`), max 5 screens, no CRM integration, no email sending, no payments. UI copy is in French (vouvoiement).

## Commands

```bash
npm run dev        # Next.js dev server (Turbopack)
npm run build      # production build
npm run lint       # ESLint (flat config)
npx tsc --noEmit   # type check
npm test           # unit tests (vitest): CSV import parsing in src/lib/import
npx vitest run -t "parseDate"   # a single test by name
npm run test:db    # schema + scoring + RLS tests on embedded Postgres (PGlite), no Docker needed
npm run db:push    # apply supabase/migrations to the linked project
npm run db:types   # regenerate src/types/database.ts from the linked project
```

The repo is linked to Supabase project `pcfiacqyjramhyqqznel` (EU, Paris). `npx supabase db query --linked "<sql>"` runs SQL on it and `npx supabase db advisors --linked` audits it. Before any `npx supabase config push`, run `npx supabase config diff` and review it: non-interactive pushes apply without asking, and `supabase/config.toml` values that only come from the `supabase init` template can overwrite real hosted settings. Custom email templates are rejected until a custom SMTP is configured (free tier).

`npm run test:db` (`supabase/tests/rls.test.mjs`) applies every migration on PGlite with a stubbed `auth` schema and checks isolation between users; extend it whenever a migration touches tables, grants or policies. There is no app test runner yet. Dev-only routes (404 in production) for visual checks: `/ui` (component catalogue), `/ui/apercu` (E3) and `/ui/apercu/prospect` (the real E5 `ProspectView`, `?relance=1` for a drafted follow-up), filled with sample data from `src/app/(app)/apercu/sample-data.ts`. The visual reference is the LeadPilot mockup (`Maquette.png`, kept outside the repo in the founder's iCloud `Documents/Bizzzzness/Revenly/`); compare at ~1100 px wide, which is the viewport the mockup depicts.

## Architecture

- `src/app/(auth)` — E1 `/connexion`: split layout (form column + `AuthVisual` panel). Sign-in and sign-up tabs both use the magic link (no password, per the product architecture).
- **Import (E2)** — `src/app/(app)/import/import-wizard.tsx` (client) parses the CSV in the browser (`src/lib/import/read-file.ts`, papaparse, UTF-8/Windows-1252), guesses the column mapping (`fields.ts` synonyms, `rows.ts`), then calls the server actions in `import/actions.ts`: `startImport` (optional replace = delete all) → `importBatch` (250 rows, re-validated with `validateImportRow`, upsert on `utilisateur_id,contact_email,entreprise`, never sends `statut`) → `finishImport` (saves settings, calls `recalculer_prospects()`). The CSV "statut" column maps to `etape` (deal stage), not to the LeadPilot follow-up `statut`. Scoring lives in SQL (`recalculer_prospects_de`, security invoker) and also runs nightly via pg_cron. `/ui/import` (dev only) mounts the wizard without a session for checking steps 1–2.
- **Score explanation** — `src/lib/scoring/score.ts` re-implements the SQL scoring formula in TypeScript (keep both in sync; `score.test.ts` reuses the values asserted by `supabase/tests/rls.test.mjs`) and explains the multiplicative score with exact Shapley values against the account's average prospect (`buildScoreContext` + `explainScore`; base + Σ factor points = score, rounding residual absorbed by the largest factor). `getScoreContext()` loads it once per request; the fiche shows `ScoreExplanationCard` (factor list + `ScoreWaterfall` bridge chart), dashboard `ScoreRing`s take an `explanation` for the hover tooltip and display the explanation's score so ring and tooltip never disagree. Never present invented factors: only montant, étape and silence influence the score.
- **AI follow-ups** — `src/app/api/relances/generer/route.ts` (Route Handler, not a server action, because it streams): checks the session, the hourly limit and `ANTHROPIC_API_KEY`, calls `anthropic.beta.messages.stream` (`claude-opus-5-5`, effort `low`, `fallbacks: "default"` with beta `server-side-fallback-2026-07-01`), streams NDJSON events (`FollowupStreamEvent` in `src/lib/ai/followup-format.ts`), then inserts the row in `relances` with the user's client (RLS). Prompt and tone instructions live in `src/lib/ai/followup.ts`; prospect data is wrapped in `<donnees_prospect>` and declared as data, never instructions (CSV notes are untrusted). The signature is appended server-side, never generated. Client side: `FollowupPanel` in `src/app/(app)/prospects/[id]/prospect-actions.tsx`. UI tone labels differ from DB values (`formel` = Professionnel, `chaleureux` = Amical). "Ouvrir dans Gmail" is a plain `<a target="_blank">` to the Gmail compose URL built by `src/lib/gmail.ts` (`buildGmailComposeUrl`, encodeURIComponent - never URLSearchParams, Gmail doesn't read `+` as a space; body dropped above ~7.5k chars and copied to the clipboard instead). Keep it a real link: a `window.open` after an `await` is blocked as a popup. Opening Gmail stamps `copiee_le` like the copy button.
- `src/app/(app)` — E2 `/import`, E3 `/tableau-de-bord`, E4 `/prospects`, E5 `/prospects/[id]`; shared layout = `AppSidebar` + `CommandMenuProvider` (⌘K palette and "G then D/P/I" shortcuts). There is no top bar: each page renders `PageContainer` > `PageHeader` (title + description + actions, or breadcrumb + back link on E5).
- `src/components/ui` — shadcn/ui primitives, **restyled to the spec**: Button variants are `primary | secondary | soft | ghost | danger | link` and sizes `lg | md | sm | icon | icon-sm` (not shadcn's defaults). Prefer editing these files over adding one-off styles.
- `src/components/shared` — product components (StatusBadge/StatusMenu, ScoreGauge, SilenceDays, KpiCard, UploadZone, CsvFormatCard, Stepper, AiFollowupBlock, InitialsAvatar, EmptyState, Field). They are presentational and controlled: business logic is passed in via props/callbacks.
- `src/lib/prospects.ts` — display vocabulary matching DB enums (`statut`, `etape`, tones) and score thresholds (≥70 fort, ≥40 moyen). `src/lib/format.ts` — French formats (`48 300 €`, `1,2 M€`, dates).
- **Database** — `supabase/migrations/` is the source of truth: 3 tables (`utilisateurs` 1—n `prospects` 1—n `relances`), Postgres enums (`statut_prospect`, `etape_affaire`, `ton_relance`), RLS on every table (owner = `auth.uid()`), column-level grants on `utilisateurs` (only settings are updatable), a trigger creating `utilisateurs` on sign-up, and `tableau_de_bord()` (security invoker) for E3 KPIs. `relances` → `prospects` uses a composite FK `(prospect_id, utilisateur_id)` so a follow-up cannot point at another user's prospect. Never add a 4th table (V1 constraint). After a migration: `npm run db:types`, then `src/lib/prospects.ts` derives its enums from `Constants` in `src/types/database.ts`.
- **Auth** — magic link only (no passwords). `/connexion` → server action `requestMagicLink` (same response whether or not the account exists) → email link → `src/app/auth/confirm/route.ts` (`token_hash` via `verifyOtp`, or PKCE `code`) → `?suivant=` destination or first-run `/import`. `src/middleware.ts` refreshes the session with `getClaims()` and redirects unauthenticated requests (public paths in `src/lib/auth/routes.ts`); every protected page/action also calls `requireUser()` (`src/lib/auth/session.ts`). Redirect targets always go through `safeRedirectPath`. Sign-out: `src/lib/auth/actions.ts`, from the sidebar account menu.
- **Data access** — server-only reads in `src/lib/data/prospects.ts` (React `cache`, user client so RLS applies, explicit `utilisateur_id` filter for index use); mutations are server actions in `src/app/(app)/actions.ts` returning `{ ok } | { ok: false, message }` (French, user-facing) and revalidating the `(app)` layout. `(app)/layout.tsx` is `force-dynamic`.
- `src/lib/supabase/{client,server,middleware}.ts` — typed `@supabase/ssr` clients (`Database`). Env vars in `.env.example`; `NEXT_PUBLIC_SITE_URL` is mandatory in production (magic-link URLs never use the Host header).

## Design system

All visual tokens live in `src/app/globals.css` (Tailwind v4 `@theme inline`, no tailwind.config); values were measured on the mockup. Never hard-code colours: use token classes (`bg-surface`, `bg-surface-tinted`, `text-foreground-secondary`, `bg-primary-soft`, `bg-warning-soft text-warning`, `bg-sidebar`, …) and the type scale `text-display | text-kpi | text-title | text-section | text-body | text-dense | text-caption`. Any new custom `text-*` size must also be registered in `src/lib/utils.ts`, otherwise tailwind-merge treats it as a colour and drops it next to `text-foreground`. Look: dark slate sidebar, light grey-blue page background, white cards (radius 12, `shadow-card`, very light border), pastel badges (soft background + saturated text, radius 6), indigo primary `#5d64f4`. Amounts, scores and dates use `tabular-nums`. Light theme only in V1.

Premium layer (2026 refresh): the body carries fixed radial indigo/violet halos; `glass` (`@utility` in globals.css) gives frosted cards (KPI cards); shadows `shadow-card | shadow-elevated | shadow-glow | shadow-ai`; accents `accent-violet` / `accent-blue` are for AI-flavoured details only (AI block, `MovingBorderButton` in `src/components/shared/moving-border-button.tsx`, sidebar active indicator) - keep them rare. Animations go through `src/components/motion/motion.tsx` (`FadeIn`, `Stagger`/`StaggerItem`, framer-motion) under a root `MotionProvider` with `reducedMotion="user"`; keep them short (≤ 400 ms, no bounce). Components passed a Lucide icon from a server page (e.g. `KpiCard`) must stay server components - animate them by wrapping in `StaggerItem`. `/ui/apercu` (dev only) renders the full shell + dashboard with sample data, no session needed, for visual checks.

Dashboard (E3) is a "command center", not a table: `src/components/dashboard/dashboard-view.tsx` (presentational, fed by `tableau-de-bord/page.tsx` with real data and by the dev preview with sample data - keep both in sync through this single component) = dark `DashboardHero` (aurora, `CountUp` hero number, `ProgressRing`, `MovingBorderButton` "Démarrer la session de relance" opening the top prospect) → `PriorityCards` (top 3) → `FollowUpQueue` (ranks 4-10) + `SilenceChart`. Hero colours use the `hero*` tokens. The "Brief du matin" is a secondary side panel (`morning-brief-panel.tsx`, button next to "À relancer en priorité"), built by `src/lib/brief/brief.ts` from real data, no AI (recoverable money, optional commission from `utilisateurs.taux_commission`, action of the day, today's progress, "Pourquoi prioritaire ?" from `ScoreFactor.shortLabel`). The founder chose to keep the dark hero as the home screen: do not promote the brief back into it.

## Deployment

Vercel, region `cdg1` (`vercel.json`, next to Supabase eu-west-3). Env vars: `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`, `NEXT_PUBLIC_SITE_URL` (production URL, required), `ANTHROPIC_API_KEY` (server only). Supabase Auth must list the production URL as Site URL and in Redirect URLs (`https://<domaine>/**`), otherwise magic links point to localhost.

## Conventions

- Dependencies are pinned to exact versions; pick releases at least two weeks old.
- When adding shadcn components (`npx shadcn@4.20.1 add <name>`), check the generated imports: the CLI once resolved `cn` to an unrelated npm package named `cn` instead of `@/lib/utils`.
